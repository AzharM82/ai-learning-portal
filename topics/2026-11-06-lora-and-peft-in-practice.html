LoRA and PEFT in practice: fine-tuning a small model hands-on

Full fine-tuning copies and updates every weight — for a 7B model that means gradients, optimizer states, and a full checkpoint per task. LoRA freezes the base model and learns only a tiny low-rank correction on top of it. You get a task-specific model for megabytes, not gigabytes, and you can train it on hardware you actually have.

02 The one-idea version

Do not rewrite the book — train a small correction slip that sits on top of it. LoRA hypothesizes that the change a task needs, ΔW, has low intrinsic rank, so instead of learning a full d×k matrix you learn ΔW = BA, where B is d×r and A is r×k with r ≪ min(d,k). The frozen base keeps all its general knowledge; the two small matrices learn only the direction of the task. At deployment you either merge BA into W for zero extra latency, or keep it as a swappable adapter file.

03 The picture: frozen base + low-rank update

One weight matrix, two paths. The big path never trains. The small path is all you save, ship, and swap.

04 How it works

Six mechanics: freeze, factorize, configure, target, quantize if you must, and prove it.

1

Freeze the base, train only the adapter

Load the pretrained model, set its weights to not require gradients, and wrap it with PEFT: LoraConfig + get_peft_model(). Hugging Face’s quicktour makes the scale concrete — wrapping Llama-3.2-1B with r=8 leaves 524,288 trainable parameters out of 1.24B, or 0.04%. No gradients or Adam states for the frozen 99.96% is where the memory saving actually comes from; you still pay to store and run the base forward and backward.

2

Factorize the update: ΔW = BA, scaled by alpha/r

For each targeted linear layer, LoRA learns A (r×k, Gaussian/Kaiming init) and B (d×r, zero init), so ΔW starts at exactly zero and training starts from the base model’s behavior, not a perturbation of it. The forward pass is h = W0x + (alpha/r)·BAx. Rank r is capacity: r=4–8 often suffices for style/format, r=16–32 for harder tasks. Do not raise r by default — doubling r doubles adapter params and can overfit a small dataset faster.

3

Target the right modules — start with attention, expand deliberately

The original paper adapted the attention projections (Wq and Wv gave the best budget trade-off). In PEFT that is target_modules=["q_proj","v_proj"]. QLoRA’s ablations found adapting all linear layers — attention plus MLP (q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj) — was needed to match full fine-tuning on its tasks. Rule: start narrow, evaluate, then widen. Targeting everything from the start hides which layers actually mattered and inflates the adapter for no measured gain.

4

Train with LoRA hyperparameters, not full-fine-tuning ones

Use a learning rate roughly an order of magnitude higher than full fine-tuning — e.g. 1e-4 to 2e-4 for a small LLM instead of 1e-5 to 2e-5 — because only the small matrices move. Set lora_dropout around 0.05 for small datasets, keep epochs low (often 2–3 passes, watching eval loss), and log print_trainable_parameters() in every run so a config typo that trains 0% or 100% is caught immediately. Save with save_pretrained(): PEFT writes only adapter_config.json + adapter_model.safetensors — megabytes, not a model copy.

5

Use QLoRA when the base itself does not fit comfortably

QLoRA keeps the same LoRA idea and quantizes the frozen base to 4-bit NormalFloat (NF4), with double quantization of the quantization constants and paged optimizers to handle spikes. Gradients flow through the dequantized weights into the LoRA adapters, which train in higher precision. That is how Dettmers et al. fine-tuned a 65B model on a single 48GB GPU. In PEFT: load with BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4"), call prepare_model_for_kbit_training(), then attach LoRA as usual. Quantization saves base memory — it does not make a bad dataset good.

6

Evaluate, then merge or swap — never merge on faith

Hold out a real eval set and compare three things: base model, base + adapter (unmerged), and — if you plan to ship merged — the merged model. They should agree within noise; if merged differs, you have a dtype or base-version bug. Merging (merge_and_unload()) bakes BA into W0 and removes any adapter latency, ideal for a single-task deployment. Keeping adapters separate is better when one base serves many tasks: load the base once, load_adapter() / set_adapter() per task, and version each adapter with the exact base model ID and revision it was trained against.

05 Code sketch

A minimal, realistic PEFT run: 4-bit base (QLoRA-style), LoRA on all linear layers, train, save only the adapter, then merge.

# pip install transformers peft trl bitsandbytes datasets
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
import torch

BASE = "meta-llama/Llama-3.2-3B-Instruct"  # pin a revision in real runs
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16,
                         bnb_4bit_use_double_quant=True)
model = AutoModelForCausalLM.from_pretrained(BASE, quantization_config=bnb,
                                             device_map="auto")
model = prepare_model_for_kbit_training(model)
tok = AutoTokenizer.from_pretrained(BASE)

cfg = LoraConfig(r=16, lora_alpha=32, lora_dropout=0.05, bias="none",
                 task_type="CAUSAL_LM",
                 target_modules=["q_proj","k_proj","v_proj","o_proj",
                                 "gate_proj","up_proj","down_proj"])
model = get_peft_model(model, cfg)
model.print_trainable_parameters()  # expect well under 1% trainable

# ... train with Trainer / SFTTrainer at lr ~1e-4 to 2e-4, 2-3 epochs ...
model.save_pretrained("out/my-adapter")  # MBs: config + adapter weights only
merged = model.merge_and_unload()       # only after evals pass
merged.save_pretrained("out/merged"); tok.save_pretrained("out/merged")

06 Failure modes

Five ways LoRA runs disappoint — and the one-line fix for each.

1

Expecting LoRA to teach brand-new knowledgeFix: use RAG for facts that must be current or citable, reserve LoRA for behavior, format, and style, and consider full fine-tuning only for deep domain shifts with lots of data.

A rank-16 update is a steering correction, not a textbook. Teams train LoRA on a pile of documents hoping the model will memorize them, then discover it hallucinates the same facts with more confidence. Low rank is the point — and the limit.

2

Rank and targets chosen by folkloreFix: run a small sweep — r in {8, 16, 32}, attention-only vs all-linear — on your eval set and keep the smallest config that clears the bar.

Copying r=64 and alpha=16 from a blog (scaling 0.25) or r=8 on all layers for a hard task both fail silently: one overfits and crawls, the other underfits and gets declared “LoRA doesn’t work.” Capacity, scaling, and placement are one decision, not three defaults.

3

Full-fine-tuning learning rate on a LoRA runFix: start near 1e-4 to 2e-4 for the adapter, watch train/eval loss separately, and stop when eval flattens — LoRA overfits small datasets in a few epochs.

At 2e-5 the adapter barely moves and the run looks like a null result; at 1e-3 without dropout it memorizes 500 examples and loses the base model’s generality on everything else. The symptom is misread as a data problem either way.

4

Adapter / base mismatch in productionFix: record base model ID + revision + tokenizer in the adapter metadata, load adapters only against that exact base, and smoke-test merged vs unmerged outputs in CI.

An adapter trained against one base checkpoint gets loaded onto a newer revision, a different quantization, or a different tokenizer. Nothing crashes — outputs just degrade. Adapters are diffs; a diff applied to the wrong file is corruption with good formatting.

5

No held-out eval — vibes as the acceptance testFix: freeze a 50-200 example eval set before training, score base vs adapter on it, and ship only if the adapter wins on the target task without regressing a general sanity set.

Three cherry-picked prompts look great, so the adapter ships. In production it turns out training taught the format of the examples including their length and hedging, and accuracy on real inputs is unchanged or worse. LoRA is cheap to train and therefore cheap to fool yourself with.

10 Flashcards

Click a card (or focus it and press Enter / Space) to flip it.

PEFT
Parameter-Efficient Fine-Tuning: the family of methods (LoRA, adapters, prefix/prompt tuning) that freeze most of a pretrained model and train only a small added or selected parameter set, aiming for full-fine-tuning quality at a fraction of the cost.
LoRA update
ΔW = BA, with A: r×k and B: d×r, r ≪ min(d,k). The adapted weight is W₀ + (alpha/r)·BA. Only A and B train; W₀ stays frozen.
Rank (r)
The bottleneck dimension of the LoRA update and its capacity knob. Higher r = more trainable params and expressiveness, more overfitting risk. Common starts: 8 for narrow tasks, 16–32 for broader ones — chosen by eval, not folklore.
Alpha and scaling
LoRA scales the update by alpha/r. Changing r without considering alpha changes the effective step size. A common pattern is alpha = 2×r (scaling 2), but what matters is the ratio, tuned with the learning rate.
target_modules
Which linear layers get LoRA adapters. Original paper: attention q/v. QLoRA practice: all linear layers (attention + MLP) to match full fine-tuning. Start narrow, widen only on eval evidence.
QLoRA / NF4
LoRA over a frozen 4-bit NormalFloat-quantized base, plus double quantization and paged optimizers. Cuts base memory drastically (65B on one 48GB GPU in the paper) while adapters train in higher precision.
Adapter checkpoint
What PEFT saves: adapter_config.json + adapter_model.safetensors — just the A/B weights, typically megabytes. It is a diff against one exact base model ID + revision, not a standalone model.
Merging
merge_and_unload() bakes BA into W₀, producing a standalone model with no adapter latency. Right for single-task serving; wrong when you need cheap per-request switching between many adapters.
Zero-init B
B starts at zero so ΔW = 0 at step 0: the model behaves exactly like the base at the start of training, and every change afterward is learned from data — no random perturbation to unlearn.

11 Reach for this when…

A model needs a task’s format, tone, or workflow — not new facts — classification labels in your schema, support replies in your voice, code in your repo’s conventions. That is a low-rank correction’s home turf: a few thousand good examples and a rank-16 adapter.
Full fine-tuning does not fit your GPU, budget, or variant count — one base, many customers/tasks, or a single 24–48GB card. LoRA trains under 1% of parameters; QLoRA shrinks the frozen base to 4-bit so the run fits at all.
You need to iterate or roll back cheaply — adapters are megabyte diffs you can version, A/B, swap per request, and delete without touching the base. If an experiment might be thrown away by Friday, it should be an adapter, not a forked model.
