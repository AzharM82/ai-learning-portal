Streaming UX for AI products

A chat product that waits 8 seconds then drops the whole answer at once feels broken. The same 8-second answer streamed token by token feels instant. Streaming UX is the craft of closing that gap: proxying token deltas to the browser without buffering, rendering partial markdown safely, and designing the stream's state machine — submitted, streaming, stopped, done, failed — so the UI is never lying.

02 The one-idea version

Streaming trades total wait for perceived wait: the only latency number users feel is time-to-first-token (TTFT). The wire gives you token deltas over SSE; the craft is everything after — proxying without buffering, appending (never replacing) chunks, healing incomplete markdown so the render never flickers, and keeping the UI honest about five states: submitted, streaming, stopped, done, failed.

04 How it works

Six mechanics. Each is a concrete action, not a slogan.

1

Ask the provider for deltas, not a document

Set stream=True and you get a sequence of text deltas over SSE (server-sent events): one long-lived HTTP response, data: lines, and a [DONE] terminator. Each chunk carries only the new text — the client must accumulate. SSE is one-way and browser-native (EventSource); reach for WebSockets only if the conversation also needs client-to-server pushes mid-stream.

2

Proxy through your server — never from the browser

Calling the provider from client-side JavaScript leaks your API key to every user. Your server holds the key, calls the provider, and forwards each chunk to the browser as it arrives. Set the flush headers on your response (Content-Type: text/event-stream, Cache-Control: no-cache, X-Accel-Buffering: no for nginx) and flush per chunk — any layer that buffers turns your stream into a surprise 8-second blocking request.

3

Append deltas to a buffer; render incrementally

Maintain one growing string per response: buffer += delta. Re-render from the buffer each time a chunk lands — never render the raw chunk alone, or mid-word boundaries will corrupt code blocks, links, and lists. The buffer is also your recovery asset: on a dropped connection, the partial text is what you keep, and you resume or retry from there.

4

Heal partial markdown before it reaches the renderer

Tokens don't respect markdown boundaries: the stream will hand you **bo with the closing ** still on the way. Feeding that to a plain renderer flips the page between raw asterisks and bold text every chunk. Run a self-healing pass (Vercel's remend / Streamdown auto-close unterminated bold, italic, code, links, and math) so the render converges smoothly as tokens arrive.

5

Model the stream as a state machine, not a boolean

Five states: submitted (waiting for first token — show an honest "thinking" indicator), streaming (tokens arriving — show a caret), stopped (user aborted — normal, not an error), done (terminator received), failed (dropped or errored). Give the user a stop button backed by AbortController; aborting must also cancel the server-side request, or the meter keeps running on text nobody reads.

6

Instrument TTFT, not just total latency

Log time-to-first-token and inter-token pacing alongside total duration. A 0.8s TTFT with 10s total feels instant; an 8s spinner for a 10s total feels broken — same model, same cost. If TTFT is slow, the fix is upstream (faster first chunk: shorter prompts, warmer models, provider choice), not in the renderer.

05 Code sketch

A minimal streaming proxy: the API key stays on the server, chunks flush to the browser as they arrive.

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from openai import OpenAI
import json

app = FastAPI()
client = OpenAI()  # key lives on the server, never in the browser

def token_events(question: str):
    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": question}],
        stream=True,
    )
    for chunk in stream:
        if d := chunk.choices[0].delta.content:   # delta: new text only
            yield f"data: {json.dumps({'delta': d})}\n\n"
    yield "data: [DONE]\n\n"   # terminator: the client trusts only this

@app.post("/api/chat")
async def chat(q: str):
    return StreamingResponse(
        token_events(q),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache",
                 "X-Accel-Buffering": "no"},  # nginx must not buffer
    )

06 Failure modes

Named pitfalls, each with a one-line fix.

F1

A proxy that silently buffers the whole streamFix: set text/event-stream, Cache-Control: no-cache, X-Accel-Buffering: no, and flush per chunk — then verify with curl that chunks arrive over time, not all at once at the end.

F2

Rendering raw chunks without healing the markdownFix: run a self-healing pass (remend / Streamdown) on the buffer before rendering — it auto-closes unterminated bold, italic, code, links, and math so partial tokens render smoothly.

F3

Treating a dropped connection as a finished answerFix: the only completion signal is the terminator event ([DONE] / response.completed) — a stream that ends without it is interrupted: keep the partial text visible, mark it incomplete, and offer retry.

F4

No stop button — or a stop button that doesn't stop the meterFix: back the stop button with AbortController, and make abort cancel the server-side provider request too — otherwise generation (and billing) continues on text nobody reads.

F5

Optimizing total latency while users watch a spinnerFix: instrument time-to-first-token separately from total duration — shaving TTFT under ~1s does more for perceived speed than any total-latency optimization nobody sees.

F6

Calling the provider API directly from the browserFix: the API key must live on the server — proxy the stream through your own endpoint, which also gives you auth, logging, event normalization, and a place to attach guardrails.

10 Flashcards

Click or press Enter/Space to flip each card.

SSE (Server-Sent Events)
A one-way streaming protocol over plain HTTP: one long-lived response, text/event-stream content type, data: lines, and a [DONE] terminator. Browser-native via EventSource — no WebSocket needed for token streams.
TTFT
Time-to-first-token: how long until the user sees anything. The only latency number users feel. A 0.8s TTFT with 10s total feels instant; an 8s spinner for the same answer feels broken.
Text delta
Each stream chunk carries only the NEW text since the last chunk — not the whole response. The client must append (buffer += delta), never replace. Rendering a chunk alone corrupts mid-word boundaries.
[DONE] / terminator event
The one completion signal you can trust. A stream that ends without its terminator is interrupted, not finished — keep the partial text, mark it incomplete, offer retry.
X-Accel-Buffering: no
The nginx header that disables response buffering. Without it, proxies hold your whole stream and deliver it at the end — your carefully built streaming UX degrades into an 8-second spinner.
Markdown healing (remend)
Self-healing markdown for streams: auto-closes unterminated bold, italic, code, links, and math before rendering. The stream gives you "**bo" with the closing "**" still on the way — heal it or the page flickers.
AbortController
What backs the stop button. Cancels the in-flight stream — but it must also cancel the server-side provider request, or generation and billing keep running on text nobody reads.
Streamdown
Vercel's streaming-optimized markdown renderer (replaces react-markdown for AI UIs). Combines remend healing with remark rendering, streaming-aware animation, and code/math/diagram plugins.
The stream's five states
submitted (waiting for first token), streaming (tokens arriving), stopped (user aborted — normal, not an error), done (terminator received), failed (dropped or errored). Design honest UI for each.

11 Reach for this when…

Users stare at a spinner for seconds before anything appears — stream the tokens; getting first meaningful content under ~1s TTFT matters more than any total-latency optimization.
The chat UI shows raw ** or flickers between raw and rendered text mid-generation — heal partial markdown on the buffer (remend / Streamdown) before every render.
Streams work locally but arrive all-at-once in production — a proxy is buffering: set the flush headers at every layer and verify with curl that chunks arrive incrementally.
