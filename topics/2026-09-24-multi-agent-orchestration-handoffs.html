Multi-agent orchestration and handoffs

A team of agents is an organizational design problem, not a model problem. Split work only when subtasks are genuinely independent (parallelism wins) or a specialist must own what comes next (ownership wins). Every hop compounds unreliability and multiplies the token bill — so orchestration is the discipline of making each handoff explicit: one owner per decision, a written memo, and one writer.

02 The one-idea version

Agents coordinate like people: one job each, and handoffs are where teams win or lose. A good handoff is a written memo — objective, what’s known, the exact output shape, what counts as done. A bad handoff is a dumped transcript and a shrug. Most multi-agent systems would work better as one agent (Cognition and Anthropic agree on that much); the ones that earn a second agent do it for parallelism on independent subtasks or isolated context, with the token bill on the same scorecard as quality.

03 The visual

Two topologies, one rule: workers return summaries; exactly one agent owns the write.

04 How it works

Seven mechanics. Each is one concrete move.

1

Earn the second agent

Default to one agent with good tools and memory. Anthropic’s production data: multi-agent systems burn ~15× the tokens of a chat, and agents on partial context make conflicting decisions a later step must clean up. Split only when the tool count becomes unmanageable in one prompt (OpenAI’s rule), the work genuinely parallelizes, or subtasks need walled-off context. The bill is a feature’s cost — score it next to quality.

2

Pick the topology by who owns the final answer

Orchestrator-workers: a lead decomposes, workers fan out in parallel, the lead synthesizes — for open-ended breadth research. Decentralized handoff: control transfers to a specialist and triage exits — for support flows where the specialist must own the conversation. Manager-as-tools: specialists exposed as tools, the manager keeps control after each step — when the manager needs the final say. Sequential pipeline: fixed assembly lines where every step is known.

3

Scope each agent like a job description

One role, one prompt, only the tools its role needs — with distinct, well-written descriptions. The classic Anthropic failure: vague delegation (“research the semiconductor shortage”) sent three subagents duplicating the same searches while real gaps went unexplored. Specialists need an objective, an output format, tool guidance, and explicit task boundaries, or coordination collapses.

4

Hand off with a written memo, never the raw transcript

Every ownership transfer carries a packet: objective (one sentence), known facts (so work isn’t redone), output format (exact shape expected), tried already (dead ends), acceptance criteria (what counts as done), boundaries (when to stop). Teach the orchestrator how to delegate — detailed task descriptions were Anthropic’s primary lever against duplicated work and gaps. A memo without these sections is a bug.

5

Wall off worker context; feed the lead compressed summaries

Subagents run in separate context windows and return condensed 1–2k-token summaries — this compression is the whole point (Anthropic: “subagents facilitate compression”). The lead synthesizes summaries, never raw dumps. If workers pass full transcripts back up, you’ve rebuilt the single-agent context limit with extra steps and 15× the tokens.

6

Scale effort to query complexity — and cap it in code

Prompt the scale rules explicitly: simple fact-finding = 1 agent, 3–10 tool calls; comparisons = 2–4 subagents; deep research = 10+ with divided responsibilities. Then enforce the ceilings in code: max subagent count, max delegation depth, max tool calls per agent. Early Anthropic agents spawned 50 subagents for a simple query — prompting alone didn’t fix that; budgets do.

7

Evaluate at the seams, not the steps

A multi-agent system never follows the same path twice, so don’t test steps — test outcomes and reasonable process. Start evaluating with small samples (effect sizes are huge early), watch the trace, and hunt coordination failures specifically: duplicated work, missing handoff memos, ownership violations, effort overkill. Every added hop has to justify its existence in the eval, or it gets collapsed back to one agent.

05 Code sketch

The handoff pattern in ~25 lines (OpenAI Agents SDK). The proof of a real handoff: result.last_agent is the specialist, not triage.

from agents import Agent, Runner

refund_agent = Agent(
    name="Refund specialist",
    instructions="Handle refunds per policy REF-01. Collect the order id, "
                 "call lookup_order then issue_refund, hand back a one-line receipt.",
    tools=[lookup_order, issue_refund],
)
shipping_agent = Agent(
    name="Shipping specialist",
    instructions="Answer tracking questions with track_package. "
                 "Reply with a one-line status and the ETA.",
    tools=[track_package],
)
triage = Agent(
    name="Triage",
    instructions="Classify the request, then hand off to the specialist. "
                 "Never answer the request yourself.",
    handoffs=[refund_agent, shipping_agent],
)

result = Runner.run_sync(triage, "Where is order #48210?")
# transfer_to_shipping_specialist is generated from the handoff list
print(result.last_agent.name)   # Shipping specialist
print(result.final_output)      # one-line status + ETA

06 Failure modes

Named pitfalls, each with the one-line fix.

F1

The vague handoffFix: brief every delegation with objective + output format + tool guidance + boundaries — treat a missing section as a bug.

“Research the semiconductor shortage” produced three subagents duplicating 2021 auto-crisis searches while current supply chains went unexplored. Vague delegation gets you duplicated work and invisible gaps — Anthropic’s production post-mortem names this failure mode #2.

F2

Unbounded spawningFix: prompt the scale rules (effort ∝ complexity) and enforce max subagents, max depth, and max tool calls in code — budgets bind loops, politeness doesn’t.

Early agents spun up 50 subagents for a simple query and scoured the web endlessly for nonexistent sources. Effort-judgment is a known agent weakness; if the ceiling lives only in the prompt, it won’t hold.

F3

Ownership violationsFix: single-writer rule — workers return summaries; only the lead (or the current handoff owner) mutates shared state.

Two agents acting on partial context make conflicting decisions a later step has to clean up. Handoffs transfer ownership explicitly — control moves; it is never duplicated. The manager pattern keeps writes single-threaded by design.

F4

The 15× token billFix: compressed subagent summaries, separate worker windows, and cost on the eval scorecard — kill hops that don’t earn their keep.

Anthropic’s data: agents use ~4× chat tokens, multi-agent systems ~15×. Every hop re-spends context. Token usage alone explained 80% of the score variance — which means most of the win is just spending more compute, and you should buy it deliberately or not at all.

F5

No handoff-back pathFix: declare the return route up front — when the specialist is done, or the task escalates, control returns to triage or a human.

A handoff with no way back strands the conversation: the specialist finishes, the user needs something else, and nobody owns the thread. Every handoff lists its exit conditions — including escalation to a human.

F6

Delegating into a shared-context domainFix: keep one agent for tightly coupled, interdependent work; reach for many only where subtasks are independent.

Most coding tasks have fewer truly parallelizable subtasks than they look, and agents are bad at real-time coordination. Multi-agent excels at breadth-first, context-heavy, tool-rich work — research, evals, parallel information gathering. Everything else: one agent, good tools, good memory.

08 Sample prompts

Copy-paste ready. Each one targets a different seam of multi-agent work.

DELEGATION BRIEF RULE — paste into the lead agent’s instructions

When you delegate to a subagent, your task brief MUST contain all five sections — a brief missing any of them is a bug: OBJECTIVE: one sentence — what success looks like. OUTPUT FORMAT: the exact shape of the answer (schema, length, citation style). TOOLS AND SOURCES: which tools to use, in what order; which sources are authoritative. KNOWN FACTS: what we already know, so nothing is researched twice. BOUNDARIES: what NOT to do, when to stop (max sources, max tool calls), and when to escalate back instead of guessing. Scale effort to the query: simple facts get 1 agent and 3–10 tool calls; comparisons get 2–4 subagents; deep research gets 10+ with divided responsibilities. Never spawn more than 12 subagents. Every subagent returns a compressed summary (1–2k tokens), never a raw transcript.

HANDOFF MEMO TEMPLATE — fill in at every ownership transfer

HANDOFF MEMO — {{from_agent}} → {{to_agent}} — {{timestamp}} OBJECTIVE: {{what the receiving agent must accomplish, one sentence}} KNOWN FACTS: {{verified facts so far — do not re-derive these}} TRIED ALREADY: {{dead ends and failed approaches — do not repeat}} ACCEPTANCE CRITERIA: {{what counts as done, measurable}} OUTPUT FORMAT: {{exact shape of the deliverable}} RETURN PATH: {{when done or blocked, hand back to {{from_agent}} with a one-paragraph status; escalate to a human if {{condition}}}} The receiving agent owns this task from here. Ownership transfers, never duplicates.

TRACE AUDITOR — find coordination failures in a multi-agent run

Review this multi-agent trace and report ONLY coordination failures, one per line: 1. DUPLICATED WORK — two agents doing the same research or tool calls. Quote both lines. 2. MISSING HANDOFF MEMO — an ownership transfer with no objective, known facts, or acceptance criteria. 3. OWNERSHIP VIOLATION — two agents writing to the same shared state, or a worker answering instead of summarizing. 4. EFFORT OVERKILL — subagent count or tool calls far beyond the task's complexity. 5. SPIN WITHOUT PROGRESS — an agent looping or re-asking without new information. For each finding: name the failure, quote the offending lines, and state the one-line fix (brief template, single-writer rule, effort cap, handoff-back path, or step budget). If a category has no finding, say "none found".

Where multi-agent doesn’t fit
Tasks needing shared full context, tight real-time coordination, or heavy inter-agent dependencies (most coding work). Default to one agent with good tools and memory there — a second agent is a cost you pay for parallelism or isolation, and it must earn it.

11 Reach for this when…

The job genuinely splits into independent subtasks and one context window can’t hold it all — reach for orchestrator-workers: workers fan out in separate windows, return compressed summaries, the lead synthesizes. This is the 90.2% shape.
A specialist must own the conversation from here on — reach for decentralized handoffs: triage exits, the specialist owns the thread, and the handoff-back path is declared up front (support triage → refunds).
One agent’s tool count or prompt complexity breaks the single prompt — reach for the manager pattern: specialists scoped to one role each, exposed as tools, one manager keeping the final say after every step.
