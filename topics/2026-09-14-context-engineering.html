Context engineering: what actually goes into the window

Prompt engineering asks how to phrase the request. Context engineering asks what the model gets to see — and ruthlessly curates it. Master the attention budget and your agents get sharper instead of noisier.

02 The one-idea version

An LLM can only attend to so much at once — every token in the window competes for its focus. Context engineering is the discipline of giving the model the smallest set of high-signal tokens it needs at each step: the right instructions, the right tools, the right facts, and nothing else. Curate, don't dump.

03 The visual

The universe of possible information is huge. The window is finite. Everything between them is a curation decision.

04 How it works

Seven mechanics, straight from Anthropic's canonical framing and the practitioner consensus. Apply them in order.

1

Treat the window as an attention budget, not storage

Every token competes for focus, and recall precision degrades as the window fills — context rot. The goal is the smallest set of high-signal tokens that maximizes the chance of the desired outcome, not the largest set that fits.

2

Write system prompts at the right altitude

Too rigid and you get brittle, hardcoded behavior; too vague and the model hallucinates your intent. Aim for the Goldilocks zone: specific heuristics, organized into labeled sections (<instructions>, ## Tool guidance), and refined by watching real failures — never by stuffing in every edge case.

3

Keep a minimal, unambiguous tool set

Tools are context too — their definitions and every output consume the budget. Give tools clear names, self-contained behavior, and token-efficient returns. Rule of thumb: if you, the engineer, can't say which tool fits a situation, neither can the model. Cut until each tool's job is obvious.

4

Retrieve just in time, not just in case

Don't preload everything. Carry lightweight references — file paths, record IDs, saved queries — and let the agent load slices on demand with tools (head, tail, grep, targeted queries). This mirrors human cognition: we don't memorize the filing cabinet, we remember where it is.

5

Compact before you hit the cliff

For long-horizon work, watch utilization and compact near the limit: summarize the trajectory (decisions, state, open questions), then restart with the summary plus pinned essentials. Waiting for a bigger window just delays the same degradation.

6

Externalize state; bring back only what's needed now

Use structured note-taking, scratchpads, and durable memory outside the window as the agent's long-term store. Each step loads only the slice relevant to the current decision — progressive disclosure, layer by layer, instead of one exhaustive dump.

7

Isolate noisy work in subagents

Exploratory, conflicting, or distracting material gets its own fresh context. A subagent chews through the mess and returns only the verdict upstream. The main agent's window stays clean; context gained and lost is engineered, not accidental.

05 Code sketch

A minimal context-window manager: token budgeting, pinned essentials, and compaction at 80%. The same three operations every production agent loop needs.

class ContextWindow:
    def __init__(self, budget_tokens, summarizer):
        self.budget = budget_tokens
        self.summarizer = summarizer  # cheap model call
        self.sections = {}            # name -> text
        self.pinned = set()           # never compacted

    def used(self):
        return sum(len(t) // 4 for t in self.sections.values())

    def add(self, name, text, pin=False):
        self.sections[name] = text
        if pin:
            self.pinned.add(name)
        if self.used() > self.budget * 0.8:
            self.compact()

    def compact(self):
        keep = {k: v for k, v in self.sections.items() if k in self.pinned}
        rest = {k: v for k, v in self.sections.items() if k not in self.pinned}
        summary = self.summarizer(
            "\n\n".join(f"[{k}]\n{v}" for k, v in rest.items()))
        keep["compaction_summary"] = summary
        self.sections = keep

06 Failure modes

Named pitfalls, each with a one-line fix. Check these before you blame the model.

✕

Context rot Fix: prune to the smallest high-signal set; put load-bearing facts first or last, never buried in the middle.

More tokens, worse recall. The middle of a long context gets skimmed and the agent starts forgetting or mixing up details.

✕

Bloated tool sets Fix: cut to a minimal viable set — no two tools with the same job, no ambiguous choice points.

Forty overlapping tools force a decision the model can't reliably make. Anthropic calls this the most common failure mode they see.

✕

Poisoning Fix: sanitize tool and RAG outputs; tag provenance; never treat retrieved data as instructions.

Untrusted content smuggles instructions or garbage into the window — injected prompts, leaked secrets, corrupted facts — and the agent obeys it.

✕

Distraction Fix: make tool returns token-efficient — bounded pages, head/tail, summaries instead of raw dumps.

Verbose tool outputs (full logs, giant tables) dominate the window and drown the actual task in noise the model must wade through.

✕

Confusion and clash Fix: isolate in a subagent with a fresh context; merge only the verdict back upstream.

Contradictory instructions or conflicting facts fight inside one window and the agent flip-flops. One context, one coherent story.

10 Flashcards

Context engineering
Curating and maintaining the optimal set of tokens the model sees at each inference step — instructions, tools, facts, history — inside a finite window.
Attention budget
The finite focus of a transformer: every token attends to every other, so each added token dilutes attention across the whole window.
Context rot
The measured effect that as tokens in the window increase, the model's recall and reasoning precision degrade. More context ≠ better performance.
Right altitude
The Goldilocks zone for system prompts: specific enough to steer behavior, flexible enough to avoid brittle hardcoded logic.
Just-in-time retrieval
Carry lightweight references (paths, IDs, queries) and load data at runtime via tools, instead of preloading everything up front.
Compaction
Summarizing a near-limit conversation and restarting with the summary plus pinned essentials — the key technique for long-horizon agents.
Minimal tool set
If you, the engineer, can't say which tool fits a situation, neither can the model. Bloated, overlapping tools are the #1 failure mode.
Structured note-taking
Persisting agent state (decisions, facts, open questions) outside the window as durable memory, so each step loads only what it needs now.
Poisoning
Untrusted tool or RAG content corrupting the context — injected instructions, garbage facts. Fix: sanitize, tag provenance, treat data as data.
Isolation (subagents)
Giving noisy, exploratory, or conflicting work its own fresh context and returning only the verdict upstream — keeping the main window clean.

11 Reach for this when…

An agent works at step 5 and wanders by step 50 — the fix is context management (compaction, note-taking, isolation), not a better prompt.
Tool outputs dominate your window — when logs and dumps fill most of it, carry references and load just-in-time instead.
You're eyeing a bigger context window to fix reliability — curate first. A bigger window full of the same noise still rots.
