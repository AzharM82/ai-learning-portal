Semantic caching to cut cost and latency

Every LLM call you skip is a call you don't pay for. A semantic cache answers "has someone already asked this?" by meaning, not spelling: embed the incoming prompt, find the nearest cached question by cosine similarity, and — if it clears your threshold — serve the stored answer in milliseconds with no model call at all. The threshold is the whole game: too loose and you confidently serve the answer to a different question.

02 The one-idea version

An exact-match cache almost never fires on human input — nobody types the same sentence twice. A semantic cache moves the key from the string to the meaning: each prompt is embedded into a vector, the cache index finds the nearest previously answered prompt, and if its cosine similarity clears a tuned threshold τ, the stored answer is served directly. On a hit the model never runs: latency drops from seconds to milliseconds and the call costs nothing. On a miss you pay one extra embedding — so the cache pays for itself at hit rates as low as ~2%, as long as the threshold keeps false hits out.

04 How it works

Six mechanics, each one a decision you'd make in production.

M1

Embed the question with a small, cheap model

The cache's own lookup cost is one embedding call. Run all-MiniLM-L6-v2 locally or call a hosted small model like text-embedding-3-small. If the embedding costs nearly as much as the call you're avoiding, the cache can never win.

M2

Store prompt + vector + response as one entry

The vector is the index, the prompt text is the audit trail (so you can inspect what actually matched), and the response is the payload. Entries carry metadata too — model id, tenant, timestamps.

M3

Match by cosine similarity against a tuned threshold τ

Serve only when the best match clears τ. Start around 0.92–0.95 for precision, then tune τ on labeled should-hit / should-not-hit pairs. Raw hit rate is a vanity metric here — false-hit rate is the real score.

M4

Scope every key per tenant and model

The lookup filter includes the user or tenant and the model version — a cache keyed on question text alone serves user A's answer to user B. Multi-tenant semantic caches are a security boundary, not just a lookup.

M5

TTL stable content; expire volatile content aggressively

Definitions, policies, and how-tos can cache for days. Prices, stock levels, "today's" anything: minutes or no caching at all. And invalidate the whole cache when the underlying model changes — yesterday's answers were shaped by yesterday's model.

M6

Run the break-even math before you build

Expected cost = h·c_hit + (1−h)·(c_embed + c_model). Caching nets positive above h* = c_embed/(c_model − c_hit) — about 2% hit rate for typical ratios. The economics are easy; the threshold quality is the hard part.

05 Code sketch

The whole pattern in 22 lines. Production versions swap the list for RedisVL or GPTCache — the flow is identical.

import time
import numpy as np

class SemanticCache:
    """Minimal in-memory semantic cache. Swap the list for RedisVL/GPTCache at scale."""

    def __init__(self, embed, threshold=0.93, ttl=3600):
        self.embed, self.threshold, self.ttl = embed, threshold, ttl
        self.entries = []  # (vector, prompt, response, expires_at)

    def ask(self, prompt, llm_call):
        q = self.embed(prompt)                       # 1. meaning of the question
        if self.entries:
            vecs = np.stack([e[0] for e in self.entries])
            sims = (vecs @ q) / (np.linalg.norm(vecs, axis=1) * np.linalg.norm(q))
            best = int(np.argmax(sims))              # nearest cached prompt
            e = self.entries[best]
            if sims[best] >= self.threshold and e[3] > time.time():
                return e[2], True              # HIT: serve, model never runs
        answer = llm_call(prompt)                    # MISS: pay embedding + full call
        self.entries.append((q, prompt, answer, time.time() + self.ttl))
        return answer, False

06 Failure modes

Named pitfalls, each with a one-line fix.

F1

A loose threshold serves confident wrong answers — "revenue in 2023" embeds almost identically to "revenue in 2024"Fix: tune τ on labeled should-hit / should-not-hit pairs, never on raw hit rate — a higher hit rate at a looser τ is how confident wrongness happens.

F2

One customer's answer served to another user from a shared cache keyed on question text aloneFix: scope every cache key by tenant/user and model; treat a leaked cache entry as a security bug, not a cache bug.

F3

An embedding-model upgrade silently invalidates the index — new vectors live in a different space than old entriesFix: pin the embedding model, version cache keys with the model name, and rebuild the index when the model changes.

F4

Stale answers outlive reality — cached prices, policies, or model behavior changed underneathFix: set TTLs by content volatility (minutes for anything time-sensitive), and invalidate the whole cache on underlying-model upgrades.

F5

The cache costs more than it saves — embeddings plus vector storage on traffic with no repeat rateFix: run the break-even math first (h* ≈ c_embed/(c_model − c_hit)) and disable the cache if measured hit rate sits below it.

10 Flashcards

Click or press Enter/Space to flip each card.

Semantic cache
An LLM response cache that matches prompts by meaning (embedding similarity), not exact text. A rephrased question can hit a cached answer — and the model never runs.
Cosine similarity
The cosine of the angle between two embedding vectors: 1 = identical direction (same meaning), 0 = unrelated. With normalized embeddings it reduces to a dot product.
τ — the similarity threshold
The cutoff that decides hit vs miss. Start around 0.92–0.95 for precision. The whole game: tune it on labeled should-hit/should-not-hit pairs, never on raw hit rate.
False hit
A near-neighbor prompt that clears τ but means something different — served confidently, cheaply, and wrong. The signature failure of a loose threshold.
Key scoping
Cache keys must include tenant/user and model — not just the question text. Without it, user A's cached answer leaks to user B, and that's a security bug.
TTL by volatility
Cache stable content (definitions, policies) for days; give volatile facts (prices, "today's" anything) minutes or no caching at all. Invalidate everything on model upgrades.
Embedding drift
Upgrading the embedding model puts new vectors in a different space than stored entries — old matches go wrong or die. Pin the model, version keys with its name, rebuild on upgrade.
Break-even hit rate
h* = c_embed / (c_model − c_hit) ≈ 2% for typical ratios. Caching pays at surprisingly low hit rates; the constraint is threshold quality, not the cost math.

11 Reach for this when…

The same stable questions arrive in many phrasings (support, docs, policies) and the LLM bill is climbing — embed once and serve by meaning instead of paying full token price per rephrasing.
Users wait seconds for deterministic answers — a cache hit answers in milliseconds with zero model calls, which no model upgrade can beat.
A spend review shows heavy cost on repeated classification, extraction, or FAQ-style calls — the cheapest LLM call is the one you never make.
