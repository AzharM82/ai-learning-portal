Planning and reasoning: CoT, ReAct, tree-of-thought

A language model has exactly one way to think: spend tokens. Chain-of-thought spends them on intermediate steps before the answer. ReAct spends them interleaved with tool calls, so the world corrects the chain. Tree-of-thought stops betting on a single chain and searches instead. Three techniques, one ladder — and the craft is knowing which rung a task deserves.

02 The one-idea version

There is no silent thinking inside an LLM — the scratchpad is the thinking. CoT gives the model scratch space: intermediate tokens before the answer. ReAct notices the scratchpad can be wrong in a checkable way, so it interleaves thought with tool calls and lets observations correct the chain. Tree-of-thought notices even a grounded chain can commit too early, so it grows many branches, scores them with the model itself, and backtracks out of dead ends. Chain → loop → search: each rung buys reliability at the cost of tokens.

04 How it works

Six mechanics: the scratchpad, the loop that checks it, and the tree that stops betting on it.

1

Chain-of-thought: make the model write intermediate steps before the answer

Give a few exemplars where each input is followed by a reasoning trace before the output (Wei et al., 2022) — or go zero-shot with "let's think step by step". Why it works: reasoning abilities emerge with scale (~100B+ parameters), and CoT turns the fixed compute per answer into compute allocated across intermediate tokens. Eight exemplars took PaLM 540B to state-of-the-art on GSM8K math word problems, beating fine-tuned GPT-3 with a verifier. Gains are real on arithmetic, commonsense, and symbolic tasks — but they're a scale-gated property, not a universal prompt trick.

2

Self-consistency: sample multiple chains, let them vote

When diverse reasoning paths can converge on one destination, sample N chains (temperature > 0) and take the majority answer. It's the cheapest reliability upgrade on the ladder: no tools, no tree — just more rolls of the dice, and it disproportionately helps tasks where many routes lead to the same correct answer. It does nothing when the model is systematically wrong or missing the knowledge; five confident copies of a misconception still lose. Pair it with the rule below: it tells you how sure the model is, not whether it's right.

3

ReAct: Thought → Action → Observation — interleaved, not sequenced

Augment the model's action space with a language action: a "thought" that updates the context but touches no environment (Yao et al., 2022). The loop: a reasoning trace induces the plan and picks a tool, your code executes the tool, the observation re-enters the prompt, the next thought revises the plan. Reasoning traces help track and update action plans and handle exceptions; actions let the model reach outside its weights — Wikipedia lookups, APIs, code execution. This is the core loop inside most production agents (LangChain, LlamaIndex, the OpenAI Agents SDK): few of them hand-code anything else by default.

4

The observation is the error-corrector: CoT compounds, ReAct grounds

CoT's fatal flaw is error propagation: once a wrong step enters the chain, every later step builds on it — there is no mechanism to be corrected. ReAct fixes exactly this: on HotpotQA and FEVER it beats CoT by interacting with a simple Wikipedia API mid-chain, checking claims against retrieved evidence instead of trusting its own trace. Design for it: a factual claim should be followed by an action whose observation tests it. The logged traces are a bonus — they make agent behavior debuggable: you can see precisely where the reasoning went off the rails.

5

Tree-of-thought: decompose, generate candidates, self-evaluate, search, backtrack

When the first move decides everything — puzzles, planning, writing — a single chain commits too early. ToT generalizes the chain to a tree of coherent "thoughts" (Yao et al., 2023): (1) decompose the problem into thought-steps; (2) generate candidate next thoughts; (3) evaluate them with the model itself as judge (scores or votes); (4) search with BFS or DFS, backtracking out of dead ends to the best-scored branch. On Game of 24, GPT-4 with CoT solved 4%; ToT solved 74%. The price is many more model calls — so this rung is for planning-heavy tasks, not for lookups that a chain or a tool call handles fine.

6

Climb the ladder, and budget every loop

Apply the lightest technique that works: direct answer → zero-shot CoT → few-shot CoT → self-consistency → ReAct → ToT. Measure at each rung; most tasks stop at CoT or ReAct. And every loop needs a step budget and an exit contract (max N iterations, then a forced "Final Answer:") — an unbounded ReAct agent is a token furnace with a looping bug. Most production agent failures live in the scaffold (parser, budget, stop condition), not in the prompt text.

05 Code sketch

The whole ReAct loop in 22 lines: the model proposes, your code executes, the budget enforces the stop.

import re, json

TOOLS = {"search": lambda q: wikipedia(q)}   # your real tool functions

SYSTEM = """You are a ReAct agent. Loop Thought, then either:
Action: {"tool": "search", "args": "..."} or Final Answer: ...
Observation: tool output. Max 8 steps."""

def react(question, llm, max_steps=8):
    trace = SYSTEM + f"\nQuestion: {question}\n"
    for _ in range(max_steps):          # the step budget: never unbounded
        out = llm(trace).strip()              # model emits Thought + next move
        trace += out + "\n"
        if out.startswith("Final Answer:"):  # the exit contract
            return out.split("Final Answer:", 1)[1].strip()
        m = re.search(r'Action: ({.*})', out)
        tool, args = json.loads(m.group(1)).values()
        trace += f"Observation: {TOOLS[tool](args)}\n"  # YOU execute, not the model
    raise RuntimeError("step budget exhausted")

06 Failure modes

Named pitfalls, each with a one-line fix. Almost all of them are a rung mismatch, a missing budget, or an unchecked chain.

×

CoT hallucinates down a confident wrong chain Fix: ground it — interleave tool actions (ReAct) so observations check claims mid-chain; never let a factual step pass unobserved.

Error propagation is CoT's structural flaw: each step inherits the previous step's mistakes with no corrective mechanism. Longer chains aren't better chains — they're longer cascades. The fix is architectural, not stylistic: facts get looked up, not reasoned into existence.

×

The ReAct loop never terminates Fix: hard step budget (max N) plus an explicit exit contract — "Final Answer:" — enforced in code, not requested in prose.

The model doesn't know it's looping; from inside the trace every step feels like progress. Asking nicely for termination is not a strategy. Budget the loop, force the final answer at the budget, and raise on exhaustion so the failure is visible instead of expensive.

×

Unparseable actions: the model emits almost-JSON Fix: emit actions as structured outputs (see 2026-09-21) — typed JSON via grammar/constraint, with one repair attempt then a clean stop, never a retry spiral.

A regex over free-form prose is a parser shaped like a bug. The action line is a machine contract: constrain the decoder to the schema, validate the call before executing, and treat repeated parse failures as a scaffold error to surface — not a loop to re-enter.

×

ToT cost explosion on a lookup problem Fix: rung-match first — reserve trees for planning where early decisions are pivotal; bound depth/branching, prune aggressively, evaluate cheaply.

A tree search that grows candidates for a single-hop fact lookup is a sports car in a school zone. Each candidate is a model call; the score multiplies fast. ToT's 74%-on-Game-of-24 result is real — and so is the bill. Cost the search before you grow it.

×

Reasoning theater: CoT on a small model adds tokens, not accuracy Fix: CoT gains emerge at scale — on small models measure the delta per rung; drop CoT where it adds latency without accuracy.

Chain-of-thought is not incantation; the Wei et al. gains were measured on models large enough to use the scratchpad. On a small model, "let's think step by step" often produces longer, equally wrong answers. The ladder is empirical: promote a technique only when the eval says so.

08 Sample prompts

Copy-paste starters. One builds the chain, one scaffolds the loop, one specs the tree.

THE CHAIN BUILDER

Build a chain-of-thought prompt for this task: {{describe the task and one correct input→output example}}. Write it as few-shot: 3–5 exemplars, each showing the intermediate reasoning steps BEFORE the final answer, with the reasoning written the way a careful engineer would actually think (no leaps, no invented facts). Then give: (1) the zero-shot fallback version using "let's think step by step"; (2) a self-consistency plan — sample size and voting rule; (3) the rung test: how will I measure whether CoT beats a direct answer on my eval set before I ship it?

THE REACT SCAFFOLD

Design the ReAct scaffold for my agent. Task: {{describe the task}}. Tools available: {{list each tool with its inputs, outputs, and what it CANNOT do}}. Specify: (1) the system prompt — Thought/Action/Observation contract, the exact action JSON schema, and the "Final Answer:" exit rule; (2) the parser — how actions are extracted and validated (and what happens on a parse failure); (3) the step budget and forced-stop behavior at the budget; (4) the grounding rule — which claims MUST be backed by an observation before the final answer; (5) what gets logged for debugging a broken trajectory. Flag the tool call most likely to loop and say how the budget catches it.

THE TREE EXPLORER

Spec out a Tree-of-Thought search for this planning problem: {{describe the problem and why the first move decides the outcome}}. Define: (1) the "thought" unit — what one step of the decomposition looks like; (2) candidate generation — how many candidates per node, and the prompt that generates them; (3) the self-evaluation rubric the model uses to score partial states (sure / maybe / impossible, or 0–10 with the one-line criteria); (4) search strategy — BFS vs DFS and the backtracking rule; (5) pruning — when a branch gets cut; (6) a cost estimate: candidates × depth × calls, and the rung test — prove CoT or ReAct fails first on my eval before paying for the tree.

10 Flashcards

Click a card — or tab to it and press Enter — to flip it.

Chain-of-thought
Make the model write intermediate reasoning steps before the answer — few-shot exemplars with traces, or zero-shot "let's think step by step". Spends tokens on the steps; emerges at scale.
Self-consistency
Sample N reasoning chains at temperature > 0 and take the majority answer. Helps when diverse paths converge; fails when all chains share the same systematic error.
ReAct
Synergizing Reasoning and Acting (Yao et al., 2022): interleave verbal reasoning traces with task-specific tool actions in a loop. Reasoning guides action; action grounds reasoning.
Thought → Action → Observation
The ReAct rhythm: Thought (a language action that touches no environment — it plans) → Action (a real tool call, executed by your code) → Observation (the result, fed back into the prompt).
Observation: the error-corrector
CoT compounds errors — once wrong, nothing pulls the chain back. An observation mid-chain (a lookup, a tool result) tests claims against reality and breaks error propagation.
Tree of thoughts
Generalize the chain to a tree of coherent "thoughts": generate candidate next thoughts, evaluate them with the model itself, search with BFS/DFS, backtrack out of dead ends. Game of 24: 4% → 74%.
Thought evaluation
The ToT step that scores partial states — the model judges its own branches (scores or votes) so search can prune losers and expand winners. The judge quality bounds the whole tree.
Backtracking
When a tree branch dies, return to the best-scored surviving branch and continue. This is what a chain cannot do: un-commit from a bad early decision.
Step budget + exit contract
Every agent loop needs a max-iterations budget and an enforced exit ("Final Answer:"), implemented in code. Asking the model to stop politely is not a strategy.
The reasoning ladder
Direct answer → zero-shot CoT → few-shot CoT → self-consistency → ReAct → ToT. Use the lightest rung that works; promote only when the eval says the cheaper rung fails.

11 Reach for this when…

The model's answer changes with the work shown — multi-step math, symbolic reasoning, anything where a direct answer is a guess. Start with zero-shot CoT, promote to exemplars with traces, sample-and-vote when paths converge.
The model must check facts or touch the world mid-thought — multi-hop questions, live data, any claim that needs a source. Reach for ReAct: Thought → Action → Observation, with a step budget and an exit contract.
The first decision decides the outcome and wrong branches are cheap to abandon — planning, puzzles, search over strategies. Reach for tree-of-thought: generate candidates, self-evaluate, prune, backtrack.
