Synthetic data generation for training and evals

Labeled data is the bottleneck on almost every AI project — so manufacture it. A teacher LLM expands a small human seed set into thousands of schema-correct rows, a judge LLM plus rule checks throw away the junk, and decontamination keeps your evals honest. Done as a pipeline, synthetic data is the cheapest way to get both a training set you can trust and evals before real traffic exists.

02 The one-idea version

Treat the teacher as a data factory, not a model to copy. A small human seed set anchors what “good” looks like; the teacher expands it into thousands of rows shaped to your loss function; a judge model plus hard rules discards the bottom slice; decontamination keeps your evals honest. The dataset is the product, not the prompt — an 80K-row clean synthetic set beats a 100K-row pile of raw generations every time.

03 The pipeline, visually

Synthetic data is a pipeline with filters, not a single prompt. Every stage exists to remove a specific failure.

04 How it works

Six mechanics. Each one is a concrete decision you make before generating a single row.

1

Shape rows to the loss function first

SFT wants (instruction, response); DPO/IPO wants (prompt, chosen, rejected); agents want full tool-call trajectories; RAG wants (query, chunks, gold answer). Generic text fits no loss function — pick the schema before the first generation call, because the schema is what the pipeline optimizes.

2

Anchor generation in a small real seed

Write 150–200 human examples or pull real corpus chunks first. The seed anchors the distribution so generations mimic real task shapes instead of drifting into generic teacher-flavored output. This is the self-instruct pattern: bootstrap from seeds, then let the teacher expand them.

3

Build a pipeline, not a prompt

Chain load → generate → judge → filter → export as repeatable steps (Distilabel’s Pipeline/Step/Task DAG, or the synthetic-data-kit ingest→generate→export CLI). Pipelines give you retries, caching, versioned prompts, and reproducible runs; a one-off prompt gives you a one-off dataset.

4

Control diversity explicitly

Put diversity instructions in the generator prompt, vary temperature and seed, generate hard negatives, evolve complexity along axes (evol-instruct), and mix multiple teachers. Then measure it — cluster row embeddings and check coverage — instead of eyeballing it. Diversity is a metric, not a hope.

5

Judge, then filter, in two passes

Score every row with a judge model on a rubric — correctness, faithfulness, instruction adherence, safety — plus rule checks (valid JSON, schema-parses, well-formed tool calls). Work in two passes: score a 5–10% sample first, and only run the full judge pass if a meaningful slice fails. Then drop the bottom ~10–20%.

6

Decontaminate before you trust anything

Dedupe exact and near-duplicate rows, then check n-gram and embedding overlap between your synthetic set and every benchmark you report on. Keep a 5–10% held-out real slice as the honest regression check. Leaked rows silently inflate benchmark scores — and once they do, nobody trusts the eval again.

05 Code sketch

A Distilabel-style generate-then-judge pipeline, with the filter that makes it production-grade.

from distilabel.pipeline import Pipeline
from distilabel.steps.tasks import TextGeneration, UltraFeedback
from distilabel.models import InferenceEndpointsLLM

teacher = InferenceEndpointsLLM(
    model_id="meta-llama/Meta-Llama-3.1-8B-Instruct",
    generation_kwargs={"temperature": 0.8, "max_new_tokens": 512},
)

with Pipeline(name="synthetic-qa") as pipe:
    gen = TextGeneration(llm=teacher)   # seeds -> (instruction, response)
    judge = UltraFeedback(llm=teacher)  # rubric-score every row

if __name__ == "__main__":
    distiset = pipe.run(dataset="my-org/seed-instructions", split="train")
    rows = distiset["default"]["train"].to_list()
    keep = [r for r in rows
            if r["ratings"][0]["rating"] >= 4   # drop the bottom slice
            and schema_valid(r)]                # rule checks: parses, well-formed
    save_jsonl("synthetic_train.jsonl", keep)  # never train on raw output

06 Failure modes

The four ways synthetic datasets go bad — each with the fix.

1

Mode collapse: every row sounds like the teacherFix: mix 2–3 teacher models, keep real rows in the blend, add explicit diversity instructions, and verify coverage by clustering row embeddings.

2

Training on raw generator outputFix: the judge-filter pass is non-optional. A 100K-row set with 20% junk underperforms an 80K clean set — filter first, train second.

3

Label leakage: the generator saw the answer while writing the questionFix: keep labels hidden during generation; spot-check generated pairs against held-out labels before they enter the training set.

4

Eval contamination: synthetic rows overlap your benchmarkFix: exact + semantic dedupe, n-gram/embedding overlap checks against every reported eval, and a held-out real slice as the regression check.

08 Sample prompts

Three prompts from the pipeline: generate with diversity, judge with a rubric, build eval rows.

PROMPT 1 · DIVERSITY-CONTROLLED GENERATOR

You generate training instructions for an LLM. Here are 5 seed instructions: <SEEDS> Generate 10 NEW instructions. Rules: - Each one must come from a DIFFERENT domain than the seeds (rotate: science, coding, business writing, math, everyday reasoning). - Vary difficulty: 3 easy, 4 medium, 3 hard. Vary length: some one-liners, some multi-step. - No instruction may share more than 5 consecutive words with any seed. - Output a JSON array of strings only, no commentary.

PROMPT 2 · RUBRIC JUDGE

You are a data-quality judge. Score this (instruction, response) pair 1-5 on each rubric: - correctness: is the response factually/logically right? - faithfulness: does it stay grounded, no invented facts? - instruction-following: does it do exactly what was asked? - safety: no disallowed content, no PII. Instruction: <INSTRUCTION> Response: <RESPONSE> Output JSON only: {"correctness": n, "faithfulness": n, "instruction_following": n, "safety": n, "keep": true|false, "reason": "one line"}. Set keep=false if any score is below 3.

PROMPT 3 · RAG EVAL ROW BUILDER

You build evaluation rows for a RAG system. Given this document chunk: <CHUNK> Write 3 questions a real user would ask that are ANSWERABLE from this chunk only, plus the gold answer for each. Rules: - The gold answer must be entailed by the chunk — no outside knowledge. - If a question can't be answered from the chunk, write "UNANSWERABLE" instead of guessing. - Output JSON only: [{"question": "...", "answer": "..."}].

10 Flashcards

Click or press Enter/Space to flip. Ten cards.

Self-instruct
Bootstrap a dataset from a small human seed set: the teacher generates new instructions from the seeds, then generates responses for them. The seed anchors the distribution.
Evol-instruct
Iteratively rewrite instructions to be harder or more constrained along complexity axes — depth, breadth, constraints — so the dataset covers difficulty, not just volume.
Schema per recipe
SFT needs (instruction, response); DPO needs (prompt, chosen, rejected); agents need tool-call trajectories; RAG needs (query, chunks, gold answer). The schema must match the loss function.
Seed anchoring
150–200 human examples (or real corpus chunks) that ground generation in real task shapes. Without seeds, generations drift into generic teacher-flavored output.
Distilabel pipeline
Load → generate → judge → filter → export as a repeatable Pipeline/Step/Task DAG. Gives retries, caching, versioned prompts, and reproducible datasets — not one-off prompts.
Judge model
A second LLM pass that scores every generated row on a rubric (correctness, faithfulness, instruction adherence, safety) plus rule checks — the filter that makes synthetic data trainable.
Two-pass filtering
Score a 5–10% sample first to estimate quality; run the full judge pass only if a meaningful slice fails. Then drop the bottom ~10–20% of rows before training.
Hard negatives
Deliberately near-miss examples (semantically similar but wrong) generated alongside positives — e.g. Distilabel triplets — that force the model to learn real distinctions, not shortcuts.
Decontamination
Exact + semantic dedupe and n-gram/embedding overlap checks between synthetic rows and every reported eval. Leaked rows silently inflate benchmark scores and destroy trust.
Mode collapse
When every generated row sounds like the teacher: same structure, phrasing, length. Fix by mixing teachers, keeping real rows in the blend, and verifying embedding-cluster coverage.

11 Reach for this when…

Labeled data is the bottleneck — you have hundreds of examples but need tens of thousands, and hand-labeling is too slow or expensive to close the gap.
You need evals before real traffic exists — a new feature needs a graded test set on day one, so generate gold-answer rows from your docs and keep a held-out real slice.
The teacher is too expensive to serve per request — distill its knowledge into a synthetic dataset once, then fine-tune a small model on the filtered rows instead of calling the teacher forever.
